Knowledge Management

Obsidian 與 Wiki Sync 架構

這套知識庫把「聊天紀錄」和「可長期維護的知識」分開：工作對話只是來源，整理後的 Wiki 才是長期資產。

三層結構

層級角色
本機 Obsidian Vault閱讀、編輯與本機 Agent 工作區；本質上是 Git working copy
Private canonical Git repository完整知識庫、版本歷史與跨環境唯一權威來源
Public curated mirror只發布明確允許公開的整理頁面，不同步私人原始資料

為什麼 Git 才是 Canonical Source

本機與雲端 Agent 能力不同；若把本機 Vault 當唯一真相，雲端工作容易形成第二份分岔知識庫。統一以 Git 的整合分支判斷最新版本，能保留歷史、diff、PR 與回檔能力。

同步原則

  1. 先讀 Wiki policy 與 purpose。
  2. 搜尋既有主題，優先更新而不是重複建頁。
  3. 把來源證據與整理後知識分層。
  4. 更新導覽與索引。
  5. 執行連結與敏感資訊檢查。
  6. 以 docs Branch → PR → Merge 進入 canonical branch。

Obsidian 關閉時怎麼驗證

Obsidian CLI 不可用不代表 Wiki 壞掉。檔案級驗證仍可檢查 Markdown 讀取、Wikilink 唯一解析、孤立頁與死端頁；只有當內容真的缺檔、斷鏈或歧義時才應失敗。

Graph 的品質原則

Graph 應表達知識關係，而不是資料夾結構。管理檔、來源材料、日期與檔名通常不應自動變成 Wikilink；只有能幫助理解主題的關係才值得成為連結。

公開版採白名單思維：只有經過整理與敏感資訊掃描的文章才進公開鏡像；私人原始筆記不會自動同步。
