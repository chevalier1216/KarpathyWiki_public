AI Skills 使用地圖

不是把所有 Skill 每次都跑一遍，而是依任務階段選擇最適合的能力，並保留產品決策、執行範圍與驗證邊界。

分類Skill / 方法解決的問題
自創lean-mission-execution完成範圍與驗收明確的實作任務
自創visible-ux-validation取得真實操作流程與可視狀態證據
自創continuous-mission-orchestration判斷是否能繼續下一個已核准任務
自創durable-execution-handoff跨上下文、額度、機器或 Agent 邊界續作
自創wiki-sync把決策、根因與解法整理成長期知識
外部karpathy-wiki從原始來源編譯成結構化 Wiki
外部Superpowers需求探索、計畫、測試、除錯與審查方法

選用路徑

  • 需求不清楚：先用 brainstorming / planning 類方法，產品選擇仍由人決定。
  • 目標已清楚：進入 mission execution，不順便擴功能。
  • 改了 UX：補真實 UI 證據，build/headless 不足以取代。
  • 即將中斷或換 Agent：先把狀態持久化，下一個環境再重新核對 Git。
  • 形成可重用經驗：進入 wiki-sync，而不是只留在聊天紀錄。
