單機麻將：本機存檔與發布驗證

單機麻將的「續玩」並不是把牌面存起來就完成。要恢復的是完整遊戲規則狀態：輪次、牌牆、花牌、明牌、分數、風局、聽牌與吃碰槓限制。

遊玩網站 · GitHub Repository

存檔的核心要求

  • 保存完整遊戲狀態，而不是只保存 UI。
  • 重要操作完成後即自動保存，不只依賴關頁事件。
  • 加入版本欄位，避免舊存檔與新版規則互相污染。
  • 對損壞、不相容與多分頁覆蓋設計防護。

一個很典型的發布 Bug

曾出現資料邏輯已判定「損壞存檔不可繼續」，但舊 CSS 仍讓「繼續」按鈕顯示。這說明資料狀態正確不代表 UI 行為正確；發布前必須跑瀏覽器層的回歸驗證。

把 Git、測試與部署分開記錄

「push 成功」「測試成功」「部署成功」「畫面驗收成功」是四個不同事件。任何一個成功都不能替代其他階段。舊失敗 workflow 仍可能留在 Actions 歷史中，因此狀態回報必須指出對應 commit 與最新 run。

本機存檔的權衡

優點是第一階段不需要登入與後端，成本低且可離線；限制是同裝置、同瀏覽器、同網站來源。跨裝置續玩與雲端牌譜應被視為另一個需求，而不是暗示本機存檔已經支援。
