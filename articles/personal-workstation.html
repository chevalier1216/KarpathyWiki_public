PersonalWorkStation：從功能實作到可驗證交付

PersonalWorkStation 是一套個人 Web AI 工作台。專案最重要的工程經驗，不只是做出 Task、Calendar 或 AI 功能，而是建立「什麼情況才算真的完成」的證據層級。

查看公開 GitHub 專案

垂直切片優先於骨架

每個 milestone 結束時產品都必須仍可操作。UI skeleton、placeholder 或「未來可串接」入口不能當成交付。

四層完成狀態

層級能聲稱什麼不能推論什麼
程式完成Source / migration / UI 已實作外部服務已可用
自動驗證Unit / E2E / build 通過真實帳號與正式資料已通過
整合驗證OAuth / API 真實操作成功正式公開 URL 已驗收
Production 驗收正式網址操作與 persistence 通過未測的其他外部能力

Cost Guardrail

任何可能新增費用的 API、雲端服務、方案升級或自動化，在執行前都必須先確認費用與免費額度；未經明確授權不開啟新增計費。這條規則寫進 execution policy，而不是只存在聊天提醒。

Migration History 的重要教訓

Production schema 存在，不代表 migration history 就正確。曾發生資料庫結構完整，但 migration history 不一致，導致整合工具把既有 migrations 誤判為尚未執行。修復前先備份、比對 schema 與歷史，再使用官方 repair 機制補登已核對版本；不以「重跑全部 SQL」當捷徑。

Guest Preview 的隔離原則

展示版可以讓未登入訪客操作隔離的 demo data，但不能借用正式帳號、私人 Storage 或後端權限。登入後仍應先通過核准流程，再載入該使用者自己的資料與服務。

可重用排錯

  • CORS 問題先判斷 preflight 是否真的讓 POST 抵達伺服器。
  • 資料解析器的列界應以來源完整結構定位，不只看最終要顯示的子集合。
  • 月曆的星期欄位應有固定七欄語意，不能依視窗寬度自動改欄數。
  • 正式站、CI、OAuth、Migration 與資料持久化要分開保留證據。
